## 4. Technical Learnings
- **How the state is stored (explained to the owner this session):** `items.jsonl` never changes; every decision is a line appended to `work/log.jsonl`; the state is the log replayed from the top; `export` writes `work/distilled.md`. Each click is on disk at once; only Save commits and pushes. Undo is last-in-first-out with no redo. A copied document folder is an independent list (not tried), and diverged logs cannot be merged (ids collide).
- **Re-measure a stated cause before fixing it.** The S04 note "Similar takes 1.4 s per click" was the first click only.
- **`web/review.html` is read from disk on every request, but the Python modules are loaded once.** Switching branches under a running server gives a new page against old server code; restart the server after any change to `src/`.
- **Stopping the server:** `kill $(ss -ltnp | grep 8377 | grep -o 'pid=[0-9]*' | cut -d= -f2)`. `pkill -f 'src.ui todo-001'` also kills the shell that runs it, because the pattern matches its own command line.
- **Foreground `sleep` is blocked in this harness**; wait with `python3 -c 'import time; time.sleep(1)'` or a short polling loop.
- A killed background server shows up as a "failed, exit code 143/144" task notification; that is the kill, not a fault.
- `copier` is at `.venv/bin/copier`. The template's own `docs/DECISIONS.md` rows appear in the compare link but do not reach projects.
- When a PR is still open and the next piece of work touches the same files, cut the new branch from it (as `similar-cache` was from `later-mark`); once the first merges, the second is level with master.
- Still true: `gh pr edit` fails on this machine (use `gh api -X PATCH .../pulls/<n>`); re-run `.venv/bin/python scripts/make_brief.py --write` in any PR touching `TODO.md`, `docs/DECISIONS.md` or the requirements files; system `python3` is 3.11, use `.venv/bin/python`; counts may go in tracked files, item text, names and ids may not.
