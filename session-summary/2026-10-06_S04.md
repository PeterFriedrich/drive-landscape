## 4. Technical Learnings
- **Check for a newer handoff on `origin/master` before trusting the local one.** This checkout was on the merged `handoff-s02` branch and one session behind; S03 was only on origin.
- **The two cuts are not the problem with the themes; compound items are.** Do not tune `--theme-cut` to fix mixed themes before the owner has split items.
- **After a split the parts are in no theme** and nothing re-clusters them. Placement is by hand (Similar → Same theme / Same group, or "Put here"). If the owner splits hundreds of items, a "re-propose themes over what is still loose" command is the likely next need; it does not exist.
- `/api/neighbours` takes about 1.4 s on the real list because `distill.show` rebuilds TF-IDF and the full distance matrix on every call. `/api/state` is 405 KB in 0.07 s. Caching the matrix in the server (invalidate when the parts change) is the obvious speed-up.
- The page keeps the "just split" strip in browser memory only; a reload empties it, and those parts are then found under "In no theme".
- **Headless Firefox here is a snap**: it cannot write under `/tmp`, so use a folder under `~/snap/firefox/common/` with `--no-remote --profile <dir> --screenshot <png> <url>`. `--screenshot` fires at page load, before the page's `fetch` returns, so a live URL screenshots blank; inline the state JSON into a copy of the page and call `render()` to get a real picture. The owner's own Firefox was running at the time and was not disturbed.
- `gh pr view <n> --json state` before each new branch: the owner merges within minutes, but once (#14) had not yet; the page branch was then cut from `edit-commands` and fast-forwarded onto master after the merge.
- A fixture text that shares words with another item changes the made-up clustering in `tests/test_distill.py` / `tests/test_ui.py` (TF-IDF); keep added fixture sentences unrelated.
- Counts such as "756 of 1,355" are in tracked docs; item text, names and ids are not. The reads of real text this session stayed in the terminal.
- Still true from S02: `gh pr edit` fails on this machine (use `gh api -X PATCH .../pulls/<n>`); re-run `.venv/bin/python scripts/make_brief.py --write` in any PR touching `TODO.md`, `docs/DECISIONS.md` or the requirements files; system `python3` is 3.11, use `.venv/bin/python`.
