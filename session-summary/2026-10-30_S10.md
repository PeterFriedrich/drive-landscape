## 3. Technical Learnings
- **Fetch before deciding a PR's merge state.** After #40 merged I ran `copier update` on the dead branch. The stash-pop onto a stale local `origin/master` then conflicted, and I wrongly called #40 a squash merge. `git fetch` showed a normal merge (`8fa9cc6`).
  - Recovery: `git reset --hard origin/master` and re-run copier. All the changes were copier output, so nothing was lost.
  - The owner had to approve the reset, because auto mode denied it as destructive.
- **A uv venv has no pip.** Install with `uv pip install --python .venv/bin/python …`. The `.venv/bin/python -m pip install -r requirements-ci.txt` fix in S08 §5 no longer works on the server; just re-run `./bootstrap.sh`.
- **On the server's XFS disk, `du` counts uv's copy-on-write clones in full.** Measure the saving with `df -h /`. uv is set to `python-downloads = "never"` (`~/.config/uv/uv.toml`).
- **A `requirements.txt` change makes `docs/BRIEF.md` stale.** `tests/test_brief.py::test_committed_brief_is_current` fails until you run `scripts/make_brief.py --write`.
- **Not from this session:** PRs #43–#45 (live inbox, split-card parts, nearest-theme picker) landed after S09 with no handoff of their own. Their author should record them, or the next session should read those commits.
