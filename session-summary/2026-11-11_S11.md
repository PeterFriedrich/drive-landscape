## 4. Technical Learnings
- **Untested assumption:** Drive converts `text/markdown` on Doc create/update, and exports a Doc as `text/markdown`. Both are used in `src/live.py`, and the fake doesn't test them. `push` reports `not_kept_by_drive` if the round trip loses lines. **Check the first real `create` and `push` output.**
- The `push` version check leaves a small race: the owner can type between the `version()` check and the `update()`. Accepted.
- `state` groups have **no `theme` key**. To find a group's theme, scan `st["themes"][tid]["groups"]`. My first `nearest` failed with a KeyError there.
- `_theme_items(st, t)` gives a theme's items, including those inside its groups. `_distance()` rows are the originals first, then the parts.
- The page reads `web/review.html` from disk on every load (`src/ui.py:143`), so page changes need a hard refresh only; `src/` changes need a server restart.
- Synced docs (`data/DATA.md`, `docs/SPEC_*.md`) make `tests/test_brief.py` fail until you run `scripts/make_brief.py --write`. `scripts/check_doc_citations.py` warns on an uppercase `NAME.md` placeholder in a docstring, which is why `live.py` says `FILE`.
- Owner rules restated this session: **nothing is placed automatically.** Suggestions and nearest themes are buttons, never bulk moves (DECISIONS 2026-10-08).
- The owner asked whether the doc id being stored in the private repo is fine. Answer given: yes. The link alone grants nothing without sharing, and the inventory already stores every `webViewLink`. The exception: if the doc is ever shared as "anyone with the link", the link stops belonging in any repo. The owner said leave it.
